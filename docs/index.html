shARKlib

A reactive UI library for Roblox. You write functions that return Frames, the library tracks which parts of those Frames depend on which pieces of state, and it updates only those parts when the state changes.

Stable Luau Roblox

Components are just functions:

local function Counter()
  local count = sh.source(0)
  return sh.create("TextButton") {
    Text = function() return "clicks: " .. count() end,
    Activated = function() count(count() + 1) end,
  }
end

It also ships with derived values, effects, error boundaries, context, control flow helpers (show, switch, values), springs and tweens, a smooth animated layout, and a templating system for property defaults.

Installation

The simplest option is the prebuilt model:

  1. Download shARKlib.rbxm from releases.
  2. In Studio, right-click ReplicatedStorage and pick Insert from File….
  3. Require it:
local sh = require(path.to.shARKlib)

To vendor the source instead, the layout under src/shared/shARKlib is:

shARKlib/
├── init.luau            -- public API + SetTemplate / Init
├── core/                -- reactive primitives
├── instance/            -- create, apply, mount, actions, helpers
├── flow/                -- show, switch, match, indexes, values
├── animation/           -- spring, tween
├── data/                -- resource, store, selector, debounce, ...
└── tooling/             -- scheduler hooks

To build the rbxm yourself with Rojo:

rojo build shARKlib.project.json -o shARKlib.rbxm

Quick start

A counter with an animated progress bar:

local sh = require(ReplicatedStorage.shARKlib)

-- 1. register templates BEFORE Init()
sh.SetTemplate({
  Frame     = { BackgroundColor3 = Color3.fromRGB(28, 28, 32) },
  TextLabel = { TextColor3 = Color3.fromRGB(235, 235, 240) },
})
sh.SetTemplate("primary", {
  TextButton = { BackgroundColor3 = Color3.fromRGB(90, 130, 220) },
})

sh.Init() -- finalize templates, unlock the rest of the API

-- 2. mount your component
sh.mount(function()
  local count = sh.source(0)
  local progress = sh.spring(function()
    return UDim2.fromScale(math.min(count() / 10, 1), 1)
  end, 0.4, 0.7)

  return sh.create("ScreenGui") {
    sh.create("Frame") {
      Size = UDim2.fromOffset(280, 120),
      Position = UDim2.fromScale(0.5, 0.5),
      AnchorPoint = Vector2.new(0.5, 0.5),

      sh.create("TextLabel") {
        Size = UDim2.fromScale(1, 0.5),
        Text = function() return "count = " .. count() end,
      },

      sh.create("TextButton", "primary") {
        Size = UDim2.new(1, 0, 0.5, 0),
        Position = UDim2.fromScale(0, 0.5),
        Text = "Increment",
        Activated = function() count(count() + 1) end,
      },
    },
  }
end, Players.LocalPlayer.PlayerGui)

Concepts

The reactive graph

There are three primitives:

source

A mutable cell. Call with no args to read, with one to write.

derive

A cached computation. Re-runs when a dependency changes.

effect

A side effect. Runs once now, and again whenever a source it reads changes.

Reading a source inside a derive or effect automatically subscribes that scope to the source. Writing the source re-runs the scopes that read it. You don't subscribe or unsubscribe manually.

Templates and Init

SetTemplate registers property defaults per class so you don't repeat them on every instance. The first form sets the unnamed default. The second registers a named variant you can pick later with create(class, name).

sh.SetTemplate({ Frame = { BackgroundColor3 = bg } })
sh.SetTemplate("primary", { TextButton = { BackgroundColor3 = blue } })

Multiple calls merge. Later writes override earlier ones for the same key. After registering everything, call sh.Init(). It freezes the templates, builds clone sources for each class, and unlocks the rest of the API. Calling anything else before Init is an error. Calling SetTemplate after Init is also an error.

Cleanup

Every effect, derive, and component runs inside an owner scope. When the scope is disposed (because something higher up re-evaluated, or because you called the destroy callback from root or mount) its children are disposed too, its cleanup callbacks run, and any events it connected get disconnected. You rarely need to write cleanup code yourself.

Component pattern

A component is a function that returns an Instance. Local state is a closure over a source:

local function Button(props)
  local hAct, hovering = sh.hover()
  return sh.create("TextButton", "primary") {
    Text = props.label,
    Activated = props.onClick,
    BackgroundTransparency = function()
      return hovering() and 0.1 or 0
    end,
    hAct,
  }
end
